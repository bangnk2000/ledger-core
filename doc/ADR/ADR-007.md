# ADR-007 — Use Kafka for Asynchronous Event Processing

## Status

Proposed

## Context

Future architecture phases require:

* asynchronous workflows
* event-driven processing
* retries
* decoupled consumers
* eventual consistency handling

Examples:

* notification dispatch
* reconciliation
* analytics
* audit streaming

## Decision

Kafka will be introduced when asynchronous workflows become necessary.

Initial event examples:

* transfer.created
* transfer.completed
* transfer.failed

Kafka adoption will occur after:

* transactional consistency is stabilized
* idempotency handling exists
* outbox pattern is implemented

## Consequences

### Positive

* scalable async processing
* decoupled consumers
* event-driven extensibility

### Negative

* operational complexity
* ordering considerations
* duplicate processing handling
* eventual consistency complexity
