
# ADR-008 — Introduce Golang for Worker-Oriented Services

## Status

Proposed

## Context

Certain workloads are:

* concurrent
* network I/O heavy
* retry-heavy
* asynchronous
* worker-oriented

Examples:

* reconciliation workers
* notification dispatchers
* webhook processors
* retry pipelines

## Decision

Introduce Golang selectively for infrastructure-oriented workers.

Java/Spring remains the primary platform for:

* core domain logic
* transaction orchestration
* account management
* consistency-sensitive workflows

Golang will be used for:

* high-concurrency workers
* event consumers
* background processing
* retry orchestration

## Consequences

### Positive

* lightweight concurrent workers
* efficient resource usage
* simpler infrastructure services
* strong concurrency model

### Negative

* polyglot system complexity
* operational overhead
* shared tooling considerations

## Notes

Golang should not replace Java for core business transaction logic prematurely.

The primary motivation is infrastructure concurrency and worker-oriented processing.
